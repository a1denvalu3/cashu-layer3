Cashu Layer3

Protocol v3 · Denomination tokens · One HTLC per private swap · Combined Lightning melts

HODL invoice (1,000 sats, held)
             ↓ issue denomination credentials
       Alice: 1,000 sats
             ↓ private split and transfer
       Alice: 990 sats    Bob: 10 sats
                              ↓ melt 9 sats + fee reserve
                         Lightning receiver: 9 sats

      Original HTLC settles; all remaining fragments expire

Each fragment keeps its backing identity

The backing attribute h = HashToFr(domain || original_amount || payment_hash) is identical across fragments. A separate denomination key determines each fragment's value. One keyset contains independent keys for 1, 2, 4, 8 and further binary denominations. Changing a token's amount selects the wrong key and fails signature verification.

One shared witness across a private swap

Every input:  κᵢ = h · Y_h2[amountᵢ] + oᵢ · G2
Every output: Bⱼ = h · Y_h1[amountⱼ] + tⱼ · G1

One proof with witnesses (h, o₁…oₙ, t₁…tₘ)
One h shared by every equation
Public sum(inputs) = sum(outputs)

The mint checks each credential and its owner/nullifier proof, verifies the common-h proof, and spends all input nullifiers atomically. Each output gets a fresh blind signature and owner secret. Swaps cannot combine different HTLCs. Denominations are public; h, the backing hash, original amount and preimage stay hidden.

Melts combine different HTLCs

A melt reveals each backing preimage and uses public-h spending proofs bound to the exact invoice, quote, ordered inputs and change commitments. The mint pays from its own outgoing liquidity while the backing holds remain pending. It charges the invoice plus actual routing fees, rounded up to sats, within the authorized fee reserve.

The selected HTLC groups fund the payment in input order. Unused input value returns as denomination tokens under the same backing HTLC. The wallet prepares change commitments before payment; retries recover the original signatures. A 999-sat payout plus a 1-sat fee fully consumes a 1,000-sat HTLC.

Expiry is terminal

The published redemption cutoff uses the earliest accepted HTLC expiry, minus LND's early cancellation delta and the configured settlement margin. Once a preimage is known, the mint settles at full consumption or the cutoff. With no known preimage, the backing eventually times out. Settled, canceled and timed-out HTLCs make every remaining fragment worthless.

No user balances survive settlement. Collecting the whole HTLC can leave an unredeemed remainder with the mint; holders must redeem before the deadline. Disclosing a preimage gives the mint the technical ability to settle early. The delay is server policy, and the public backing list is a mint-reported snapshot.

Recovery preserves payment outcomes

All inputs and the payout hash are reserved before payment. Uncertain outcomes remain pending; only definite failure releases inputs. Confirmed fees, signatures and receipts are stored before full-consumption settlement. Payments already in flight may resolve after the cutoff. Change against a closed HTLC is reported as expired rather than converted to a user account.
